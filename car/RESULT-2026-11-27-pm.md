# Car visit 27.11, daytime: uncompressed audio and iAP2 (track on the head-up display) over the cable

Logs: `runs/20261127-134027/` (head unit logs of the separate runs: `run4-*`, `run5-*`, the last one without a prefix).
Checklist: `CHECKLIST-next-visit.md`.

## Result
- **PCM over the cable works.** The iPhone picks `PCM/44100/16/2` (and 48000) for music, `PCM/24000/16/1 for
  speechRecognition, input yes` for Siri: Siri listens through the **car microphone** (`Input: YES`,
  `AudioStreamPrepare … input = 1`) and answers through the speakers. The track buttons on the wheel now work over the
  cable (on the morning of 27.11 they did not).
- **Over the air nothing changed:** over Wi-Fi the iPhone still takes AAC-LC / AAC-ELD; the track on the head-up
  display, the buttons and Siri are as before, both with PCM and with the iAP2 adapter in the chain.
- **The track on the head-up display over the cable works** (last run): `w1` (RAM) + the iAP2 adapter + the bridge
  `--iap2-factory` (build `8da18d62…`). `mm-ipod` passed the signature check and identification ("BMW 92066",
  F30-NBTEvo-0716), and subscribed to 5000/4154/4157; PPS `iap2_wifi` `Authenticated::true`; the track on the head-up
  display changes when switching from the wheel; 420/432 packets went through the adapter in 3 minutes. The session was
  ended by the bridge's test timer (`--stop-after`, 180 s).

## What got in the way and how it was found
1. **Siri dropped the cable session (ENOSPC).** The bridge wrote the pcap to `/tmp` — this is the head unit RAM disk of
   **14 MB**; with uncompressed audio the file grew to 13 MB, the disk filled up, `MirroredRingBufferInit` for the Siri
   microphone could not create a file → `Main audio setup failed: ENOSPC` → the session was closed. Fixed: the pcap is
   written only with `BRIDGE_PCAP=1`.
2. **The bridge output over SSH broke off at 5 KB** (run 3). At the time I took this for the cause of the break, but
   run 4 with the log in a file on the head unit died the same way — from the signature request (item 3). What stopped
   the output in run 3 was not found; the bridge log is now written to `/dev/shmem/cp-bridge.log` anyway and picked up
   after the end.
3. **A break after exactly 10 s with `w1` (runs 3–5).** Not an AirPlay timer: in the same microsecond DevCtrl writes
   "Disconnection successful with the currently selected device" — Connectivity itself closes the session if `mm-ipod`
   did not connect to the phone within 10 s. The cause: the bridge's device role sent an `AuthenticationChallenge` of
   **32 bytes**, but the head unit's chip is ACP **2.0B** and signs only 20 (the iPhone over Bluetooth sends 20): chip
   status 0x80, error code 04, `mm-ipod`: "Authenticated verification error". In IDEmu the stand-in chip accepted any
   length. Fixed (`cp_iap2dev.c`: 20 bytes), the tests on the Mac were updated.
4. Without the intermediate bridge (`w1` and the plain bridge, run 5) — the same break after 10 s: over the cable the
   iPhone does not run iAP2 inside AirPlay, so the bridge "device" is needed.
